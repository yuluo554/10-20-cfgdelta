# 模拟项目题：行为级配置 diff（归一化层 + 影响分类层）

> **性质**：自拟模拟项目题（**不参赛项目题**，成果发布 GitHub **公开仓库**，署名 `yuluo554`）。
> **目标产出**：`10-20-cfgdelta`（`10-20` 为仓库编号标签，沿用本系列目录命名；GitHub 仓库名沿用 `10-20-cfgdelta`；命令名 `cfgdelta`）。
> **交付形态**：**单静态二进制 CLI**——零运行时依赖、不调外部命令、无集群交互、不需要 helm、不需要 kubectl。
> **题目定稿日期**：2026-10-20　**题目版本**：v1（首版定稿）　**查证基准日**：2026-10-20
>
> **定位宣言**：结构等价层已经很挤（dyff 1898★ / graphtage 2491★ / diffyml 127★ / diffx 89★ / confdiff 41★），但**值等价层是空的**：实测 dyff 把 `1Gi` vs `1024Mi`、`500m` vs `0.5`、以及 API Server 默认值全部报成差异并让 CI 变红。本工具做的是 **dyff 的前置归一化层 + 影响分类层**：先归一（数量 / 时长 / 类型 / YAML 布尔族），再分行为 vs 纯书写，最后只报会改变行为的那几条。**不是更好的 YAML diff，是归一化层 + 影响分类层。**

## 一、项目介绍

### 1.1 痛点

GitOps 流水线里最贵的一次红色不是"部署失败"，而是"什么都没变，CI 却红了"。两份语义等价的 manifest 在下列四种情况下会被结构化 differ 判成差异：K8s 数量单位换算、Helm values 的类型书写差异、API Server 施加的默认值、以及非 YAML 格式被 YAML 解析器硬解。

工程师的应对方式目前只有三种，都有代价：给 CI 加 `--exclude` 白名单（dyff#242 的诉求正是"想按值排除"）；把 diff 结果人工看一遍再放行（dyff#280 说的"渲染出来对真实变更几乎没有信息"）；或者干脆不 diff（HN 26283698 的原话："有时你只是想 diff 两个 k8s 对象，kubectl diff 不是干这个的工具"）。

本工具把这条链路拆成三段并各自可验证：**归一化**（把语义相同的书写折成同一个值）→ **结构无关比较**（键序/缩进/引号/注释不进差异）→ **影响分类**（只把会改变运行时行为的差异摆到门禁前面）。

### 1.2 实测的四类确定性误报（本题的存在理由）

> 红队实测版本：dyff v1.12.0、diffyml v1.8.2、confdiff 0.17.2；复现命令见 `data/README.md §一`。以下四组结果**全部为实测**，不是推测。

#### 测试A：K8s 默认值 + 数量单位（两份语义完全相同的 Deployment）

```yaml
# k1
ports: [{containerPort: 80}]
resources:
  limits:
    memory: 1Gi
    cpu: 500m
```

```yaml
# k2
ports: [{containerPort: 80, protocol: TCP}]
resources:
  limits:
    memory: 1024Mi
    cpu: 0.5
imagePullPolicy: IfNotPresent
```

dyff 输出 **4 处差异**，且 `--set-exit-code` 返回 **1**（CI 直接变红）：

| # | dyff 判定的差异 | 实际情况 |
|---|---|---|
| 1 | `+ imagePullPolicy: IfNotPresent` | API Server 默认值，语义空操作 |
| 2 | `+ protocol: TCP` | API Server 默认值，语义空操作 |
| 3 | `1Gi` → `1024Mi` | 同一数量的两种单位书写 |
| 4 | `500m` → `0.5` | 同一数量的两种单位书写 |

diffyml 给出**一模一样的 4 条**（同谱系）。

#### 测试B：Helm values 跨环境

| 项 | 环境 A | 环境 B | 语义 |
|---|---|---|---|
| replicas | `replicaCount: 3` | `"3"` | 相同（整数字面量 vs 字符串） |
| image tag | `image.tag: "1.25"` | `1.25` | 相同（版本标签不是数） |
| cpu | `500m` | `0.5` | 相同 |
| memory | `1Gi` | `1024Mi` | 相同 |
| env | 顺序不同 | — | 相同（键序无关） |

dyff 报 **5 处**，exit **1**；confdiff 加 `-l` 报 **6 处**（`env` 按下标对齐，两条各算 name+value），再加 `--array-set` 降到 **2 处**。
（**M1 复核修正 2026-10-20**：原记"仍报 5 处"与实测不符；引用 confdiff 的条数必须写明所用开关。留档见 `testdata/baseline/confdiff/B-confdiff*.out`。）

### 1.6 为什么是工具而不是让 AI 聊天算

diff 的每一步都必须是**可复算的判定**：`1Gi` 与 `1024Mi` 是否相等，取决于一套冻结的文法（`Ki Mi Gi Ti Pi Ei` 是 1024ⁿ，`k M G T P E` 是 10ⁿ）；默认值是否抵消，取决于版本化的 profile；退出码是否红，取决于影响分类表。这三件事都必须**同一输入两次跑出同一结果、退出码逐位一致**——聊天式交互没有冻结文法、没有版本化 profile、没有可断言的退出码，CI 无法依赖它。

## 二、任务要求

> **首期范围限定**：YAML / JSON 双格式 + 3 值族 + 5 个行为影响类，共 4 个必做模块 + 1 个第 8–10 天模块（M1–M5）。TOML / INI / .env / HCL 全部落在 M5，**不进 M1–M4 的验收路径**。
>
> **数值口径一律以 `data/README.md §四` 为唯一来源**（Quantity / Duration 文法、浮点禁令、序列三模式、默认值施加顺序、退出码、影响分类表）。本文出现的文法与退出码均为引用，**不得手写第二份口径**。

### 模块 1（M1）｜normalize：值等价代数引擎

- **输入**：单个配置值（来自 YAML / JSON 的标量）与其**值族声明**（由 profile 或 `--coerce-at` 指定）。
- **输出**：归一化后的**规范值**（canonical value）或显式 `indeterminate`。规范值是可比对的精确表示，不是"看起来差不多的字符串"。
- **文法与规则（全部按 `data/README.md §四` 定义一次）**：
  - **K8s Quantity**：严格按 apimachinery 文法，后缀集合为 `Ki Mi Gi Ti Pi Ei`（1024ⁿ 家族） ∪ `n u m "" k M G T P E`（10ⁿ 家族） ∪ 指数式（如 `1e3`）；规范化为**精确有理数**（分子/分母整数），**不经过浮点**。`1e3` 与 `1000` 必须判等。
  - **Go Duration**：按 Go 的 `time.ParseDuration` 文法（`ns us µs ms s m h` 及组合），规范化为**纳秒整数**。`90s` == `1m30s`，`1h` == `60m`。
  - **数值**：十进制精确规范化（去尾零、去前导零），**整值浮点折叠**（`1.0` → `1`；`1e3` → `1000`）；`1.50` == `1.5`。
  - **YAML 布尔族**：按 YAML 1.1 全族（`yes/no/on/off/true/false/TRUE/FALSE` 等）归一为 `true/false`；**字符串 `"true"` 不自动强转**，只有 `--coerce-at <path>` 显式声明该位置的值族时才按声明处理。
  - **null 三态**：`缺失（key absent）` / `显式 null` / `空字符串` **三者严格区分**，不互相折叠。
  - **百分比**：**默认当字符串**处理，仅当 profile 显式声明该位置为 ratio 时才换算。
  - **非 K8s 字节单位**（`MB` 十进 vs `MiB` 二进）：存在书写歧义 → **判 `indeterminate`，绝不静默判相等**。
- **硬纪律**：**禁止浮点参与相等判定**——任何路径上出现 `float64` 比较即视为 bug（代码评审 + 测试断言双重拦截）。
- **确定性纪律**：同一输入两次归一输出**同一规范值**；规范值的字符串表示是冻结的（排序/序列化不引入平台差异）；`indeterminate` 必须携带**理由码**（如 `ambiguous_unit_family`），不允许无理由的 `unknown`。
- **验收**：测试C 的 7 组 **100% 判等**（含 `1e3` vs `1000`）；`1Gi` vs `1000M` 判**不等**（1024³ ≠ 1000³，这是反例，必须报差异）；`MB` vs `MiB` 判 `indeterminate` 而非相等；同一输入双跑输出字节一致。

### 模块 2（M2）｜diff：结构无关比较

- **输入**：两份已解析的文档树（YAML / JSON）。
- **输出**：差异列表（每条含路径、左值、右值、差异类别）。
- **确定性纪律**：
  - **键按 UTF-8 字节序递归排序**后比较；键序差异**不产生任何差异条目**；
  - **序列三模式**，由 profile / 开关显式选择，不做自动猜测：
    - `ordered`：按位置逐项比较；
    - `set`：元素作为集合比较（顺序无关，元素按规范化后的字节序排序后比对）；
    - `keyed:<field>`：按指定字段作键对齐；**键必须唯一，出现重复键即报错退出**，不做"取第一个"；
  - **不做模糊匹配、不做相似度、不做启发式对齐**——这三样会把"不确定"伪装成"没有差异"；
  - 缩进、引号风格、行内/分行、注释：**零差异**（注释在解析阶段即丢弃，但必须在输出里标注"注释不计入比较"）。
- **验收**：键重排 / 缩进变化 / 引号风格变化 / 注释增删四类输入 → **零差异条目**；`keyed:` 模式注入重复键 → 明确报错并给出重复键路径；`set` 模式下乱序元素 → 零差异。

### 模块 3（M3）｜profile：K8s 默认值等价表

- **输入**：profile 名（带版本，如 `k8s/v1.29`）+ 两份文档。
- **输出**：施加默认值后的两侧文档（内部中间态，可 `--dump-normalized` 输出）+ 抵消后的差异列表。
- **数据形态**：**数据驱动的版本化 JSON**（随二进制内嵌或随包分发），每条含：路径模式、默认值、适用 kind、来源标注（"kubectl/API Server 默认"）。**默认值不写在代码里**。
- **核心算法**：**双侧同时施加默认值** → 相同的默认值在两侧同时出现 → 相互抵消 → **不产生差异**；若一侧**显式写了非默认值**，归一后与默认值不等 → **正确报差异**（这是防"过度静默"的关键反例）。
- **首期范围**：先做 **10 条高频默认值**（`imagePullPolicy`、`protocol`、`terminationGracePeriodSeconds`、`restartPolicy`、`dnsPolicy`、`serviceAccountName`、`revisionHistoryLimit`、`strategy.type`、`progressDeadlineSeconds`、`securityContext` 下的常见默认为候选清单，最终以 `data/README.md §四` 的版本化表为准）。
- **确定性纪律**：施加顺序固定（**外层先于内层、父先于子**；同层按路径字节序），顺序一处定义；profile 未命中任何规则时**明确降级为纯结构 diff 并在输出头部标注**，不静默假设；profile 版本号进输出头。
- **验收**：**测试A 从 4 条 → 0 条**（这是 README 首屏的核心卖点，必须截图）；显式 `imagePullPolicy: Always` 的对照组 → 仍报 1 条；profile 传入未知版本 → 明确错误退出，不静默用别的版本。

### 模块 4（M4）｜classify + gate：影响分类与 CI 门禁

- **输入**：M2/M3 的差异列表。
- **输出**：分类后的差异（每条一个影响类）+ 汇总计数 + 门禁判定。
- **影响分类（5 个行为类 + 1 个非行为类）**：
  | 类 | 判定线索（示例） |
  |---|---|
  | 资源·收缩 | 资源 limit/request 归一后**变小**，或副本数减少 |
  | 部署·收缩 | 可用副本、maxUnavailable 等使可用容量下降的变更 |
  | 镜像·变更 | image 引用变化，按 semver **细分为 major / minor / patch**；非 semver 标签（如 `latest`、`sha-` 前缀）单列 `non-semver` |
  | 接口·暴露 | Service 端口 / 类型 / selector / Ingress 路由变化 |
  | 配置·新增·移除 | env、ConfigMap key、Secret key 的增删 |
  | 纯书写 | 归一后语义相同、或只影响呈现的差异 —— **只计数，不逐条列** |
- **退出码（一处定义，逐位断言）**：`0` = 等价（无行为差异）／`1` = 有行为差异／`2` = 存在 `indeterminate`／`3` = 解析错误或用法错误。
- **门禁**：`gate --fail-on 资源·收缩,接口·暴露` —— 只有命中列出的类才返回 `1`；未列出的行为差异**照常输出但不阻断**；`indeterminate` 始终返回 `2`（除非显式 `--allow-indeterminate`）。
- **确定性纪律**：分类顺序固定（先按影响类、再按路径字节序），不依赖 map 迭代顺序；汇总计数从明细**计算得出**，不单独维护计数变量。
- **验收**：**测试B 从"5 条 exit 1" → "0 行为差异 exit 0"**；构造一条真实的资源收缩 → `gate --fail-on 资源·收缩` 返回 `1`；构造一条 `indeterminate` → 返回 `2`；构造非法 YAML → 返回 `3`。

### 模块 5（M5，第 8–10 天）｜多格式适配器

- **输入**：TOML / INI / .env / HCL 文件。
- **输出**：与 YAML/JSON 相同的内部文档树（进入 M2 之后的同一路径）。
- **纪律**：
  - **只做结构解析，不做表达式求值**：HCL 中的 `var.x`、函数调用、插值一律保留为**字面表达式节点**并标注 `unevaluated`，**不猜测求值结果**；
  - TOML 的 `[service]` 段必须解析为**表**而非字符串（对照测试D 的 dyff 噪声）；
  - .env 的引号与转义按格式自身规则处理，不做跨格式合并；
  - 解析失败一律 exit `3` 并指出行号列号。
- **验收**：测试D 的 TOML 用例 → 0 差异噪声；HCL 属性重排 → 0 差异；`unevaluated` 表达式 → 输出中可见标注且不参与相等判定。

- **完整 defaulting 表**（覆盖全部内置 kind）：首期只做高频默认值，完整表是长期维护项。
- **helm values 覆盖链**（base chart + 每环境 override 的合并求解）：需要理解 Helm 模板语义，与"不调外部命令"的形态冲突，首期不做。

## 六、边界与非目标

- **不做"更好的 YAML 结构化 diff"**：那是 dyff（1898★）/ graphtage（2491★）/ diffyml / diffx / confdiff 的领地。本题的结构比较只做到"够用且确定"——键序、缩进、引号、注释零噪声，不做彩色渲染、不做富文本输出、不做 patch 生成。
- **不做可视化 / 不做 UI**：无 TUI、无 Web、无桌面窗口、无 HTML 报告。输出是纯文本（可选 JSON）。
- **不做集群交互**：不需要 kubectl、不需要 helm、不连 API Server、不做 server-side diff、不读 kubeconfig。默认值表来自公开 manifest 语义，**不通过连集群探测**。
- **不做自动修复**：不生成 patch、不改写文件、不给"建议改成 X"。只回答"这两份是否行为等价、差异属于哪类"。
- **"零依赖"表述纪律**：只能写"**零运行时依赖 / 单静态二进制 / 不调外部命令**"；**不得宣称"无第三方库"**——构建期可以使用第三方解析库，只是运行期不分发动态依赖。
- **隐私红线**：**纯本地、零网络**。不读环境变量做隐式配置、不上传任何内容、无遥测、无账号。
- **品牌隔离**：本题只做配置文件语义比较；文档不提及任何其他项目，不复制其他项目代码。
- **首期范围限定**：YAML / JSON 双格式进首期；TOML / INI / .env / HCL 只进 M5（第 8–10 天）；完整 defaulting 表、helm values 覆盖链、多来源 env parity 一律为扩展项，**不在首期承诺交付**。
- **默认值表的诚实边界**：默认值随 K8s 版本变化，是**长期负债**。profile 必须带版本（如 `k8s/v1.29`）；未命中规则时**明确降级为纯结构 diff 并在输出头部标注**，不静默假装"已做默认值比较"。
- **`indeterminate` 的边界**：它是**一等结果**而非错误。默认只对已知族归一，未知族按原样比较；`--strict` 才把"未知族"升级为 `indeterminate`。
- **免责**：本工具不保证"语义等价 ⇒ 运行时行为一致"——只保证在**已声明的归一化规则与 profile 版本**下等价。规则外的情况一律走 `indeterminate` 或纯结构 diff，并在输出中标注。
