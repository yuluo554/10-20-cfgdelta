## 一、语言与构建：为什么是 Go

| 候选 | 单静态二进制 | 精确有理数 | 本机可验证 | 结论 |
|---|---|---|---|---|
| **Go 1.24** | ✅ `CGO_ENABLED=0` 默认产出单文件 | ✅ `math/big.Rat` | ✅ 2026-10-20 实测 `go1.24.5 windows/amd64` 可编译、`goproxy.cn` 可拉 `gopkg.in/yaml.v3` | **选中** |
| Rust 1.95 | ✅ | ✅ | ✅ 本机可用 | 备选：交叉编译链成本更高，YAML 生态分散 |
| Python 3.12 + PyInstaller | ⚠️ 冻结产物、跨平台需原生构建 | ✅ `fractions` | ✅ | 不符合"单静态二进制"第一优先 |

**构建三件**（`plan/05` K-03 锁死）：

```bash
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=<ver>" -o dist/cfgdelta ./cmd/cfgdelta
```

- `CGO_ENABLED=0` → 静态链接，无 libc 运行时依赖；
- `-trimpath` → 二进制内不残留构建机绝对路径（脱敏 + 可复现的前提）；
- `-ldflags -X main.version` → **版本号单一来源** = `VERSION` 文件，构建期注入；README 与 `--version` 两处由测试断言一致。

**第三方依赖纪律**：只允许 `gopkg.in/yaml.v3`（构建期依赖），其余全部 stdlib。对外措辞只能是"**零运行时依赖 / 单静态二进制 / 不调外部命令**"，**不得**写"无第三方库"。

## 二、分层

```
cmd/cfgdelta/main.go        入口：信号无关、只做"装配 + 退出码翻译"
  └── internal/cli          子命令解析与编排（唯一知道子命令名的地方）
        ├── internal/doc        统一内部文档树（YAML/JSON → Node）
        ├── internal/value      值族代数：quantity / duration / decimal / bool / null / ratio
        ├── internal/diff       结构无关比较（ordered / set / keyed:<field>）
        ├── internal/profile    版本化默认值表（embed JSON）+ 双侧施加
        ├── internal/classify   影响分类（5 行为类 + 纯书写）
        └── internal/exitcode   退出码单点定义（0/1/2/3 + 优先级）
```

**依赖方向单向**：`cli → {doc, value, diff, profile, classify}`；`diff → {doc, value, profile}`；`classify → {diff, value}`。**`value` 不 import 任何上层**——它是纯代数层，可单独做表驱动测试。

**为什么 `exitcode` 独立成包**：退出码是唯一对外契约（CI 直接消费），必须"一处定义、逐位断言"。任何子命令不得自己 `os.Exit(1)`，只返回 `error` 或 `exitcode.Code`。

## 三、内部文档树（`internal/doc`）

三态节点，**保留原文**是精确归一的前提：

```go
type Kind int // Scalar | Mapping | Sequence

type Node struct {
    Kind      Kind
    Tag       string          // yaml 原生 tag：!!str / !!int / !!float / !!bool / !!null
    Style     uint            // yaml 原生 style：0=plain, 1=单引号, 2=双引号（用来判"是否书写为字符串"）
    Raw       string          // 标量原文（"1Gi" / "1e3" / "yes"），normalize 层只认它
    Children  []*Node         // Mapping: [k0,v0,k1,v1,...]，保持文档顺序
    Line, Col int             // 错误定位用
}
```

- **键序无关**：比较时不依赖 `Children` 顺序，遍历前按 UTF-8 字节序排序（`sort.Slice` + `bytes.Compare`）；**不重排原始树**，只在比较器里排序，保证 `--dump-normalized` 输出仍可读。
- **注释零噪声**：`yaml.v3` 的 `Node` 默认不带 `HeadComment/LineComment`（本仓不调用 `Decode` 到 struct，也不开 `KnownFields`），注释在解析阶段即丢弃；输出头固定打印 `comments: not compared`。
- **YAML 布尔族的坑（实测）**：`yaml.v3` 按 YAML 1.2 core schema 解析，`yes` 的 tag 是 `!!str`、`Style=0`（plain）。因此 **YAML 1.1 全族归一必须由 `internal/value` 按 `Style==plain` 自行判定**——这同时天然满足"`"true"`（Style≠0）不自动强转"。
- **JSON**：`encoding/json` + `Decoder.UseNumber()`，数字原文进 `Raw`，**绝不经过 `float64`**（这正是不用 `interface{}` 反序列化的原因）。
- **多文档 YAML**：`yaml.Decoder` 循环，`---` 分隔的多个文档按序号成列表；单文档输入按单对象处理。
- **非首期格式**（TOML/INI/.env/HCL，M5）走同一 `Node`，适配器只做结构解析、不求值。

## 四、值族代数（`internal/value`）

**唯一规范值类型**（禁止浮点，K-01）：

```go
type Canonical struct {
    Family value.Family      // quantity | duration | decimal | bool | string | null
    Rat    *big.Rat          // quantity/decimal/ratio：精确有理数
    Ns     int64             // duration：纳秒整数
    Bool   bool              // bool
    Str    string            // string / null 标记
}
```

- `quantity`：文法见 `data/README.md §4.1`。后缀表用 `map[string]*big.Rat` 预计算（`Ki..Ei` = 1024ⁿ，`n..E` = 10ⁿ），指数式与后缀**互斥**。
- `duration`：§4.2，累加为 `int64` 纳秒；`90s == 1m30s` 由整数相等自然成立。
- `decimal`：§4.3，`big.Rat.SetString` 支持 `1e3` / `1.50`；规范形式 = 约分后的 Rat，整值即 `N/1`。
- `bool`：§4.4 全族表；**仅 plain 标量参与**。
- `null` 三态：`absent`（键不存在）/ `null`（`!!null`）/ `empty`（`!!str` 且 `Raw==""`），**互不折叠**。
- `ratio`：§4.6，默认不启用；显式声明时 `50%` → `1/2`。
- `indeterminate`：§4.7，`{Reason: "ambiguous_unit_family"|"unknown_family"|"unevaluated_expression"}`，**必带理由码**。

**族声明从哪来**：`--coerce-at <glob>=<family>` + profile 的 `families` 段。默认按位置推断的只有三族（quantity/duration/decimal）——它们在 K8s 语境下无歧义；**百分比与字节单位不在默认族内**。

## 五、结构比较（`internal/diff`）

```go
type Entry struct {
    Path     string   // JSON Pointer 风格：/spec/template/spec/containers/0/resources/limits/memory
                      // （set 模式例外：pointer[quoted canonical key]，见 plan/03 §三）
    Kind     EntryKind // Added | Removed | Changed | Indeterminate
    Left, Right *value.Canonical
    Reason   string   // Indeterminate 的理由码
    Class    classify.Class // classify 阶段回填
}
```

- 键排序：`sort.Strings` 的 Go 实现是字节序（UTF-8 lexicographic），与口径一致；
- 序列三模式：`--seq-mode ordered|set|keyed:<field>`（默认 `ordered`，**不做自动猜测**）；
- `keyed:` 重复键 → 返回 `exitcode.Usage` 并打印重复键路径（K-05）；
- 对齐失败的元素**成对或成单列出**，不猜配对。

## 六、profile（`internal/profile`）

- JSON 形状：`{ "name": "k8s/v1.29", "k8s_version": "1.29", "rules": [ { "kind": "Deployment", "path": "/spec/template/spec/containers/*/imagePullPolicy", "default": "IfNotPresent", "family": "string", "source": "API Server defaulting" } ] }`；
- **内嵌**：`//go:embed ../../data/profiles` 不行（embed 不能跨包上溯）→ 由 `internal/profile/embed.go` 用 `//go:embed profiles/*.json`，构建前 `go generate` 把 `data/profiles/` 同步进 `internal/profile/profiles/`，并由测试断言两份逐字节一致（**单点可编辑源 = `data/profiles/`**）；
- 双侧施加 → 相同默认值抵消；显式非默认值仍报差异（§4.11）；
- 未知版本 → `exitcode.Usage`；未命中任何规则 → 输出头 `profile_hits: 0` + `degraded: structural-only`。

## 七、确定性设计（K-02）

| 面 | 约束 |
|---|---|
| 键遍历 | 字节序排序，不依赖 Go map 迭代 |
| 数字 | `big.Rat`，不经过浮点；文本输出用有理数精确格式化 |
| 输出 | 文本与 JSON 双轨；JSON `sort_keys` 等价（手写有序编码，不用 `map`） |
| 时钟 | 运行期**不读时钟**（输出里无时间戳） |
| 环境 | 不读环境变量做隐式配置、不读 `$HOME`、不联网 |
| 双跑一致 | `cfgdelta diff ...` 同输入两次 `sha256` 相同；`selftest` 内含该项断言 |

## 八、错误与退出码

`internal/exitcode` 定义：

```go
const (
    Equal      Code = 0
    Behavioral Code = 1
    Indeterminate Code = 2
    Usage      Code = 3
)
func Combine(a, b Code) Code   // 取最高优先级 3 > 2 > 1 > 0
```

- `main` 只做一件事：`os.Exit(int(exitcode.Combine(...)))`；
- 解析错误带 `file:line:col`（`doc.ParseError`）；
- 未知值族 / 未知 profile / `keyed:` 重复键 / `--coerce-at` 未命中 → `Usage(3)`；
- `indeterminate` 存在且未 `--allow-indeterminate` → `2`（**优先于 1**，§4.12）。
